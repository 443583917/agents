## 先理解：MCP 是什么

MCP 是一个基于 JSON-RPC 的开放协议。它解决了 Agent 开发中的一个核心问题：

**以前：** 每个 Agent 框架有自己的 Tool 定义方式（`@function_tool` vs `BaseTool` vs `tool()`），工具和框架绑死。

**现在：** MCP Server 是一个独立进程，通过标准协议暴露工具。任何支持 MCP 的框架都能调用——OpenAI SDK、LangChain、Claude Desktop、Cursor。

```
# MCP Server 是一个独立进程
# 它通过 stdio（标准输入输出）或 SSE（HTTP）与外界通信

Agent (Host)                      MCP Server (独立进程)
    │                                    │
    ├── JSON-RPC Request ───────────────►│
    │   {"method":"tools/list"}          │
    │                                    │
    │◄── JSON-RPC Response ──────────────┤
    │   {"result": [                     │
    │     {"name":"get_balance", ...},   │
    │     {"name":"buy_shares", ...}     │
    │   ]}                              │
    │                                    │
    ├── JSON-RPC Request ───────────────►│
    │   {"method":"tools/call",          │
    │    "params":{"name":"get_balance", │
    │    "arguments":{"name":"Ed"}}}     │
    │                                    │
    │◄── JSON-RPC Response ──────────────┤
    │   {"result": 10000.00}             │
```

## Lab 1：Consume（消费）—— 用别人写的 MCP Server（1_lab1.ipynb）

**目标：** 不写一行 Server 代码，用 `MCPServerStdio` 连接 3 个预构建 MCP Server，让 Agent 浏览网页并存文件。

### 三个预构建 Server

```python
from agents.mcp.server import MCPServerStdio

# Server 1: 网页获取
fetch_params = {"command": "uvx", "args": ["mcp-server-fetch"]}

# Server 2: Playwright 浏览器自动化
playwright_params = {"command": "npx", "args": ["@playwright/mcp@latest"]}

# Server 3: 文件系统（限制在 sandbox/ 目录）
files_params = {
    "command": "npx",
    "args": ["-y", "@modelcontextprotocol/server-filesystem", "sandbox/"]
}
```

### 列出 MCP Server 提供的工具

```python
async with MCPServerStdio(params=fetch_params, client_session_timeout_seconds=60) as server:
    tools = await server.list_tools()
    for tool in tools:
        print(f"{tool.name}: {tool.description}")
```

### Agent 同时使用多个 MCP Server

```python
async with MCPServerStdio(params=files_params) as mcp_files:
    async with MCPServerStdio(params=playwright_params) as mcp_browser:
        agent = Agent(
            name="investigator",
            instructions="You have browser and filesystem access.",
            model="gpt-4.1-mini",
            mcp_servers=[mcp_files, mcp_browser]  # 组合多个
        )
        with trace("investigate"):
            result = await Runner.run(agent,
                "Find a recipe for Banoffee Pie, save to sandbox/banoffee.md")
```

**执行流程：**
```
Agent 收到任务
  → 决定"需要搜索"
  → 调用 Playwright MCP 的 navigate + extract_text
  → 决定"需要保存"
  → 调用 Filesystem MCP 的 write_file
  → 完成
```

**Agent 自主决定：** 先用什么工具、后用什么工具、怎么组合——完全自动。

### 你要搞懂
1. `MCPServerStdio` 是 OpenAI Agents SDK 的 MCP 集成——一个参数就连接一个 Server
2. `server.list_tools()` 查看 Server 提供了什么能力
3. Agent 的 `mcp_servers` 参数——和 `tools` 一样是工具来源
4. MCP Server 是一个独立进程——`command` + `args` 指定如何启动

## Lab 2：Build（构建）—— 写自己的 MCP Server 和 Client（2_lab2.ipynb）

**目标：** 用 FastMCP 创建 MCP Server，用原始 `ClientSession` 写 MCP Client。

### 第一步：领域模型（accounts.py）

```python
class Account(BaseModel):
    name: str
    balance: float = 0.0
    holdings: dict[str, int] = {}  # symbol -> shares

    def buy_shares(self, symbol: str, num_shares: int, price: float) -> str:
        cost = num_shares * price * 1.0005  # 含 0.05% 价差
        if self.balance >= cost:
            self.balance -= cost
            self.holdings[symbol] = self.holdings.get(symbol, 0) + num_shares
            return f"Bought {num_shares} of {symbol} for ${cost:.2f}"
        return "Insufficient balance"
```

### 第二步：FastMCP Server（accounts_server.py）

```python
from mcp.server.fastmcp import FastMCP
mcp = FastMCP("accounts_server")

@mcp.tool()
async def get_balance(name: str) -> float:
    """Get the cash balance of the given account."""
    return Account.get(name).balance

@mcp.tool()
async def buy_shares(name: str, symbol: str, num_shares: int) -> str:
    """Buy shares for the given account."""
    price = get_share_price(symbol)
    return Account.get(name).buy_shares(symbol, num_shares, price)

# 除了 tools，还有 resources——像 REST API 的数据端点
@mcp.resource("accounts://accounts_server/{name}")
async def read_account_resource(name: str) -> str:
    account = Account.get(name.lower())
    return account.report()

@mcp.resource("accounts://strategy/{name}")
async def read_strategy_resource(name: str) -> str:
    return get_strategy(name)

if __name__ == "__main__":
    mcp.run(transport='stdio')
```

**Tool vs Resource 的区别：**

| | Tool | Resource |
|------|------|------|
| 用途 | 执行操作（买/卖/查） | 读取数据（报表/配置） |
| 语义 | 动词（do something） | 名词（read something） |
| URI | 无 | `accounts://accounts_server/{name}` |
| 类比 | POST 请求 | GET 请求 |

### 第三步：原始 MCP Client（accounts_client.py）

不依赖 OpenAI Agents SDK，直接用 `mcp` 库：

```python
from mcp.client.stdio import stdio_client
from mcp import StdioServerParameters, ClientSession

params = StdioServerParameters(
    command="uv", args=["run", "accounts_server.py"], env=None
)

# 列出工具
async def list_accounts_tools():
    async with stdio_client(params) as streams:
        async with ClientSession(*streams) as session:
            await session.initialize()
            result = await session.list_tools()
            for tool in result.tools:
                print(f"{tool.name}: {tool.description}")

# 调用工具
async def call_accounts_tool(tool_name: str, tool_args: dict):
    async with stdio_client(params) as streams:
        async with ClientSession(*streams) as session:
            await session.initialize()
            result = await session.call_tool(tool_name, tool_args)
            return result.content[0].text

# 读取资源
async def read_accounts_resource(name: str):
    async with stdio_client(params) as streams:
        async with ClientSession(*streams) as session:
            await session.initialize()
            result = await session.read_resource(f"accounts://accounts_server/{name}")
            return result.contents[0].text
```

### 第四步：把 MCP 工具转成 OpenAI FunctionTool

```python
async def get_accounts_tools_openai():
    openai_tools = []
    for tool in await list_accounts_tools():
        schema = {**tool.inputSchema, "additionalProperties": False}
        openai_tool = FunctionTool(
            name=tool.name,
            description=tool.description,
            params_json_schema=schema,
            on_invoke_tool=lambda ctx, args, t=tool.name:
                call_accounts_tool(t, json.loads(args))
        )
        openai_tools.append(openai_tool)
    return openai_tools
```

### 你要搞懂
1. `@mcp.tool()` 把一个 Python 函数暴露为 MCP 工具
2. `@mcp.resource()` 暴露数据结构——有 URI，像 REST GET
3. `stdio_client` + `ClientSession` 是原始访问——不依赖任何 Agent 框架
4. `session.initialize()` 是握手——必须在调用工具前执行
5. MCP 工具可以转成 `FunctionTool`——和任何 SDK 工具混用

## Lab 3：Categorize（分类）—— 三种 MCP Server 类型（3_lab3.ipynb）

**目标：** 理解 MCP Server 的三种部署模式，引入金融数据。

### Type 1：本地独立 Server（无外部依赖）

```python
# mcp-memory-libsql: 知识图谱记忆，数据全在本地 SQLite
params = {
    "command": "npx", "args": ["-y", "mcp-memory-libsql"],
    "env": {"LIBSQL_URL": "file:./memory/ed.db"}
}

async with MCPServerStdio(params=params) as mcp_server:
    agent = Agent(..., mcp_servers=[mcp_server])

    # 第一次调用——Agent 存入记忆
    result = await Runner.run(agent, "My name's Ed. I'm an LLM engineer.")

    # 第二次调用——Agent 从持久化记忆中读取
    result = await Runner.run(agent, "What do you know about me?")
    # 输出: "You're Ed, an LLM engineer."
```

关键是记忆在两次 `Runner.run()` 之间持久化——因为 SQLite 文件保留在磁盘上。

### Type 2：本地 Server → 远程 API

```python
# Brave Search MCP Server: 本地 npx 进程，内部调用 Brave Search API
params = {
    "command": "npx", "args": ["-y", "@modelcontextprotocol/server-brave-search"],
    "env": {"BRAVE_API_KEY": os.getenv("BRAVE_API_KEY")}
}

# Polygon.io Market Server: 自定义 FastMCP，内部调用 Polygon REST API
# market_server.py
@mcp.tool()
async def lookup_share_price(symbol: str) -> float:
    return get_share_price(symbol)  # market.py 缓存到 SQLite
```

### Type 3：远程托管 Server（了解即可）

```python
# 通过 SSE（HTTP）连接远程部署的 MCP Server
from agents.mcp.server import MCPServerSse
server = MCPServerSse(params={"url": "https://mcp.example.com/sse"})
```

### Polygon.io 三层数据方案

| 方案 | 价格 | 数据 | 实现 |
|------|------|------|------|
| Free | 免费 | EOD（每日收盘后） | `market.py` 缓存整个市场到 SQLite |
| Paid | ~$29/月 | 15 分钟延迟快照 | 官方 `mcp_polygon` Server |
| Realtime | ~$200/月 | 实时逐笔成交 | 官方 `mcp_polygon` Server |

### 你要搞懂
1. Type 1（独立）→ 适合自包含的工具（记忆、计算、文件）
2. Type 2（代理）→ 适合需要外部 API 的工具（搜索、股票、邮件）
3. Type 3（远程）→ 适合企业内部服务、需要集中治理的工具
4. 免费 API 的缓存策略——SQLite 缓存避免频繁调用和速率限制

## Lab 4：Compose（组合）—— 自主交易 Agent（4_lab4.ipynb）

**目标：** 用 Agent-as-Tool 模式组合 5 个 MCP Server，构建自主交易 Agent。

### 架构

```
Trader Agent (交易员)
├── tools:
│   └── Researcher as Tool ──► Researcher Agent (研究员)
│                                ├── mcp-server-fetch (网页获取)
│                                └── brave-search (Brave 搜索)
│
└── mcp_servers:
    ├── accounts_server (账户操作)
    ├── market_server (股价查询)
    └── push_server (推送通知)
```

### Agent-as-Tool（Researcher 被包装成工具）

```python
# 研究员有独立的 MCP Server（搜索 + 网页获取）
researcher = Agent(
    name="Researcher",
    instructions="Research news and market opportunities...",
    mcp_servers=[fetch_server, brave_server],
    model="gpt-4o-mini"
)

# 把研究员包装成 Trader 的一个工具
researcher_tool = researcher.as_tool(
    tool_name="Researcher",
    tool_description="Research online for news and opportunities"
)

# 交易员持有研究员工具 + 自己的 MCP Server
trader = Agent(
    name="Trader",
    instructions="You are an autonomous equity trader...",
    tools=[researcher_tool],
    mcp_servers=[accounts_server, market_server, push_server],
    model="gpt-4o-mini"
)

result = await Runner.run(trader, "Make one trade if you see an opportunity", max_turns=30)
```

**执行流程：**
```
Trader 收到指令
  → 调用 Researcher 工具（研究机会）
    → Researcher 调用 fetch MCP（获取财经新闻）
    → Researcher 调用 brave MCP（搜索股票信息）
    → Researcher 返回分析结果
  → Trader 分析结果
  → 决定买入 AAPL
  → 调用 accounts_server 的 buy_shares
  → 调用 push_server 的 push（发送通知）
  → 完成，输出交易总结
```

### 资源读取（动态获取账户状态和策略）

```python
# 通过 MCP Resource URI 读取
account_report = await read_resource(f"accounts://accounts_server/{name}")
strategy = await read_resource(f"accounts://strategy/{name}")
```

### AsyncExitStack——干净管理多个 Server

```python
async with AsyncExitStack() as stack:
    # 同时启动多个 MCP Server，任何退出时自动全部关闭
    servers = [
        await stack.enter_async_context(
            MCPServerStdio(params, client_session_timeout_seconds=120)
        )
        for params in mcp_server_params
    ]
    # ... 使用 servers
# 退出 with 块时，所有 Server 自动关闭
```

### 你要搞懂
1. Agent-as-Tool 不是 handoff——Researcher 是 Trader 的工具，Trader 始终控制
2. Researcher 有自己独立的 MCP Server——和 Trader 的 MCP Server 完全隔离
3. `AsyncExitStack` 替代深层嵌套的 `async with`
4. Resource URI 让 Agent 动态读取配置和状态

### 调度循环（trading_floor.py）

```python
async def run_every_n_minutes():
    add_trace_processor(LogTracer())  # 注册自定义追踪器
    traders = create_traders()        # 创建 4 个交易员

    while True:
        if RUN_EVEN_WHEN_MARKET_IS_CLOSED or is_market_open():
            # 四交易员并行运行
            await asyncio.gather(*[trader.run() for trader in traders])
        else:
            print("Market is closed, skipping run")

        await asyncio.sleep(RUN_EVERY_N_MINUTES * 60)

if __name__ == "__main__":
    asyncio.run(run_every_n_minutes())
```

### 每个 Trader 的装配过程（traders.py）

```python
class Trader:
    async def run(self):
        async with AsyncExitStack() as stack:
            # 1. 启动交易员侧 MCP Server
            trader_servers = [
                MCPServerStdio(p) for p in get_trader_mcp_params()
            ]

            # 2. 启动研究员侧 MCP Server（独立的 fetch + brave + memory）
            researcher_servers = [
                MCPServerStdio(p) for p in get_researcher_mcp_params()
            ]

            # 3. 创建 Researcher Agent → 包装为 Tool
            researcher_tool = await get_researcher_tool(researcher_servers)

            # 4. 创建 Trader Agent
            trader = Agent(
                name=self.name,
                instructions=self.instructions,
                tools=[researcher_tool],
                mcp_servers=trader_servers,
                model=self.model
            )

            # 5. 运行（带追踪）
            with trace(self.name):
                result = await Runner.run(trader, self.prompt, max_turns=30)

            return result.final_output
```

### 自定义 TracingProcessor（tracers.py）

```python
from agents.tracing import TracingProcessor

class LogTracer(TracingProcessor):
    def on_trace_start(self, trace) -> None:
        """记录每个 Agent 的运行开始"""
        name = self.get_name(trace)
        if name:
            write_log(name, "trace", f"Started: {trace.name}")

    def on_span_start(self, span) -> None:
        """记录每个 span（工具调用、LLM 调用等）"""
        name = self.get_name(span)
        if name and span.span_data:
            message = f"{span.span_data.type}: {span.span_data.name}"
            write_log(name, type, message)

    def on_span_end(self, span) -> None:
        """记录 span 结束（含耗时）"""
        ...

add_trace_processor(LogTracer())
```

## 常见问题

**Q: MCP 和直接 import 函数有什么区别？**
A: `import` 的函数和 Agent 在同一个进程里，换框架就得重写。MCP Server 是独立进程，换框架只需要换 Client 连接方式，Server 代码完全不动。

**Q: 什么时候应该把工具做成 MCP Server 而不是 SDK Tool？**
A: 当你需要跨框架复用、跨语言实现、独立部署和扩展、或者团队有不同的人维护工具和 Agent 时。

**Q: stdio 和 SSE 怎么选？**
A: stdio 适合本地开发和单机部署（性能好、无网络开销）。SSE 适合远程部署、容器化、多 Agent 共享同一个 Server。

**Q: 一个 Agent 能同时用多少 MCP Server？**
A: 理论上没有限制。本课程的 Trading Floor 每个 Agent 用了 5+ 个 Server。关键是管理好子进程资源——用 `AsyncExitStack`。

**Q: MCP Server 可以用什么语言写？**
A: 任何语言。Python（FastMCP）、TypeScript（MCP SDK）、Go、Rust 都有官方或社区 SDK。Agent 不需要知道 Server 用什么语言。

**Q: MCP 和 REST API 的区别？**
A: REST API 需要 Agent 知道 URL 和参数格式。MCP 提供自动发现（`list_tools`）和标准化调用（`call_tool`）——Agent 自己探索能做什么。

**Q: 多个 Agent 能共享同一个 MCP Server 吗？**
A: 能。本课程 `trading_floor.py` 中四个交易员共享 `accounts_server` 和 `market_server`。也可以每个 Agent 有独立实例（如知识图谱记忆——每个研究员有自己的 `memory.db`）。
