# 3_crew 学习指南

> CrewAI 把 Agent Loop 封装成角色驱动的多 Agent 协作框架。如果 OpenAI SDK 是"单兵作战"，CrewAI 就是"团队协作"。

## 学习顺序（强制）

```
coder → debate → financial_researcher → stock_picker → engineering_team
 (1h)    (2h)          (3h)                 (4h)              (4h)
```

---

## 通用启动方式

5 个项目结构一致，运行方式相同：

```bash
# 进入项目目录
cd debate

# 安装依赖（如果用 UV）
uv sync

# 运行
uv run src/debate/main.py
```

每个项目都会从 `main.py` 调用 `crew.kickoff(inputs={...})`，把模板变量传给 `agents.yaml` 和 `tasks.yaml`。

## 项目 1：coder — 单 Agent 代码执行

**位置：** `coder/`  
**难度：** ⭐  
**Agent 数：** 1 | **Task 数：** 1 | **流程：** Sequential

### 学什么

最小 CrewAI 项目——一个 Agent 写 Python 代码并在 Docker 沙箱里执行。

### 核心代码

**agents.yaml:**
```yaml
coder:
  role: Python Developer
  goal: You write python code to achieve this assignment: {assignment}
  llm: gpt-4o-mini
```

**tasks.yaml:**
```yaml
coding_task:
  description: Write python code to achieve this: {assignment}
  expected_output: A text file that includes the code itself, along with the output of the code.
  agent: coder
  output_file: output/code_and_output.txt
```

**crew.py 关键配置：**
```python
@agent
def coder(self) -> Agent:
    return Agent(
        config=self.agents_config['coder'],
        verbose=True,
        allow_code_execution=True,       # 允许 Agent 执行代码
        code_execution_mode="safe",      # Docker 沙箱隔离
        max_execution_time=30,           # 超时限制（秒）
        max_retry_limit=3                # 失败重试次数
    )
```

**main.py 入口：**
```python
def run():
    inputs = {"assignment": "用莱布尼茨级数算圆周率，10000项"}
    Coder().crew().kickoff(inputs=inputs)
```

### 你要搞懂
1. `@CrewBase` + `@agent` + `@task` + `@crew` 四个装饰器的关系
2. YAML 中的模板变量 `{assignment}` 怎么通过 `kickoff(inputs=...)` 传入
3. `allow_code_execution=True` 的安全机制（需要 Docker）

## 项目 2：debate — 辩论系统

**位置：** `debate/`  
**难度：** ⭐⭐  
**Agent 数：** 2 | **Task 数：** 3 | **流程：** Sequential

### 学什么

- 一个 Agent 被多个 Task 复用（debatable 先正方后反方）
- 多 LLM 供应商混用（OpenAI + Anthropic）
- 顺序依赖：正方 → 反方 → 裁判

### 核心代码

**agents.yaml:**
```yaml
debater:
  role: A compelling debater
  goal: Present a clear argument either in favor of or against the motion. The motion is: {motion}
  llm: openai/gpt-4o-mini

judge:
  role: Decide the winner of the debate
  goal: Given arguments for and against this motion: {motion}, decide which side is more convincing
  llm: anthropic/claude-sonnet-4-6
```

**tasks.yaml — 同一个 Agent 被两个 Task 复用：**
```yaml
propose:
  description: You are proposing the motion: {motion}. Come up with a clear argument in favor.
  agent: debater                    # debater 第一次使用
  output_file: output/propose.md

oppose:
  description: You are in opposition to the motion: {motion}. Come up with a clear argument against.
  agent: debater                    # 同一个 debater，不同指令
  output_file: output/oppose.md

decide:
  description: Review the arguments presented and decide which side is more convincing.
  agent: judge                      # 不同 Agent 做裁判
  output_file: output/decide.md
```

**执行流程：**
```
kickoff({motion: "需要严格监管大模型"})
  │
  ▼
propose (debater)  ──► output/propose.md  （正方论点）
  │
  ▼
oppose (debater)   ──► output/oppose.md   （反方论点）
  │
  ▼
decide (judge)     ──► output/decide.md   （裁判判决）
```

### 你要搞懂
1. Agent 和 Task 是 N:N 关系——一个 Agent 可以被多个 Task 使用
2. `Process.sequential` 保证 Task 按 YAML 中定义的顺序执行
3. 多 LLM 供应商：`openai/gpt-4o-mini` vs `anthropic/claude-sonnet-4-6`

## 项目 3：financial_researcher — 金融研究管线

**位置：** `financial_researcher/`  
**难度：** ⭐⭐  
**Agent 数：** 2 | **Task 数：** 2 | **流程：** Sequential

### 学什么

- **Task context**：一个 Task 的输出作为另一个 Task 的输入
- **工具集成**：`SerperDevTool` 让 Agent 可以搜索网页
- 研究者 → 分析师 的经典管线模式

### 核心代码

**任务链——context 字段是关键：**
```yaml
research_task:
  description: Conduct thorough research on company {company}...
  agent: researcher

analysis_task:
  description: Analyze the research findings and create a comprehensive report on {company}...
  agent: analyst
  context:
    - research_task        # ← analyst 可以读到 researcher 的输出
  output_file: output/report.md
```

**crew.py — Agent 挂载工具：**
```python
@agent
def researcher(self) -> Agent:
    return Agent(
        config=self.agents_config['researcher'],
        verbose=True,
        tools=[SerperDevTool()]   # 网页搜索工具
    )

@agent
def analyst(self) -> Agent:
    return Agent(
        config=self.agents_config['analyst'],
        verbose=True
    )
```

**执行流程：**
```
kickoff({company: "Apple"})
  │
  ▼
researcher + SerperDevTool ──► 网页搜索结果
  │
  ▼
analyst (context: research_task) ──► output/report.md（综合报告）
```

### 你要搞懂
1. `context: [research_task]` 让 analyst 能看到 researcher 的全部输出
2. `SerperDevTool` 需要设置 `SERPER_API_KEY` 环境变量
3. 管线模式：前面 Agent 采集原始数据，后面 Agent 做分析和格式化

## 项目 4：stock_picker — 股票分析系统（最核心）

**位置：** `stock_picker/`  
**难度：** ⭐⭐⭐⭐  
**Agent 数：** 4（含 Manager） | **Task 数：** 3 | **流程：** Hierarchical

### 学什么

这是整个 3_crew 模块最重要的项目。集中演示了：
- **层级流程**：Manager Agent 动态分配任务给 3 个专家
- **Pydantic 结构化输出**：Task 输出是类型安全的 Python 对象
- **持久化记忆**：SQLite 长期记忆 + LanceDB 向量记忆
- **自定义工具**：Pushover 推送通知

### 核心架构

```
                     ┌──────────────┐
                     │   Manager    │  (gpt-4o, allow_delegation=True)
                     └──────┬───────┘
                            │ 动态委派任务
            ┌───────────────┼───────────────┐
            ▼               ▼               ▼
   ┌────────────────┐ ┌──────────┐ ┌──────────────┐
   │ Trending Finder│ │Financial │ │ Stock Picker │
   │ + SerperDevTool│ │Researcher│ │+ PushoverTool│
   │   memory=True  │ │+ Serper  │ │  memory=True │
   └────────────────┘ └──────────┘ └──────────────┘
```

### Pydantic 结构化输出

```python
from pydantic import BaseModel

class TrendingCompany(BaseModel):
    name: str
    ticker: str
    reason: str

class TrendingCompanyList(BaseModel):
    companies: list[TrendingCompany]

# Task 定义时指定输出类型
@task
def find_trending_companies(self) -> Task:
    return Task(
        config=self.tasks_config['find_trending_companies'],
        output_pydantic=TrendingCompanyList  # 不再是自由文本
    )
```

### 持久化记忆（3 种记忆系统）

```python
@crew
def crew(self) -> Crew:
    return Crew(
        agents=self.agents,
        tasks=self.tasks,
        process=Process.hierarchical,    # 层级流程
        manager_agent=manager,
        memory=True,                      # 启用记忆
        long_term_memory=LongTermMemory(
            storage=LTMSQLiteStorage(
                db_path="./memory/long_term_memory_storage.db"
            )
        ),
        short_term_memory=ShortTermMemory(
            storage=RAGStorage(
                embedder_config={
                    "provider": "openai",
                    "config": {"model": "text-embedding-3-small"}
                },
                type="short_term",
                path="./memory/"
            )
        ),
        entity_memory=EntityMemory(
            storage=RAGStorage(...)
        ),
    )
```

三种记忆的区别：
| 记忆类型 | 存储 | 内容 | 生命周期 |
|---------|------|------|---------|
| LongTermMemory | SQLite | 任务结果、发现 | 跨会话持久 |
| ShortTermMemory | LanceDB 向量库 | 当前会话上下文 | 单次 kickoff |
| EntityMemory | LanceDB 向量库 | 实体（公司、人物等） | 跨会话持久 |

### 自定义工具

```python
class PushNotificationTool(BaseTool):
    name: str = "Send a Push Notification"
    description: str = "Send a push notification to the user"

    def _run(self, message: str) -> str:
        payload = {
            "user": os.getenv("PUSHOVER_USER"),
            "token": os.getenv("PUSHOVER_TOKEN"),
            "message": message
        }
        requests.post("https://api.pushover.net/1/messages.json", data=payload)
        return '{"notification": "ok"}'
```

### 你要搞懂
1. `Process.hierarchical` vs `Process.sequential`：Manager 动态决策 vs 固定顺序
2. `output_pydantic` 让 Task 输出变成可编程的数据结构
3. 三种记忆系统的适用场景和存储后端
4. 自定义 `BaseTool` 的 `_run()` 方法实现

## 项目 5：engineering_team — 软件工程团队

**位置：** `engineering_team/`  
**难度：** ⭐⭐⭐  
**Agent 数：** 4 | **Task 数：** 4 | **流程：** Sequential

### 学什么

- 完整 SDLC 管线：需求 → 设计 → 编码 → UI → 测试
- Task context 的多级链式依赖
- Agent 代码执行（Docker 沙箱）
- 多 LLM 供应商混用

### 管线架构

```
{requirements} = "构建交易平台账户管理系统"
  │
  ▼
engineering_lead (gpt-4o) ──► design_task ──► output/accounts_design.md
  │
  ▼
backend_engineer (claude)  ──► code_task ──► accounts.py
  │  allow_code_execution=True   │
  │                              │
  ├──────────────────────────────┤
  │                              │
  ▼                              ▼
frontend_engineer (claude)   test_engineer (claude)
  ──► app.py (Gradio UI)       ──► test_accounts.py
```

### Task 链式依赖

```yaml
code_task:
  agent: backend_engineer
  context:
    - design_task           # 代码基于设计

frontend_task:
  agent: frontend_engineer
  context:
    - code_task             # UI 基于后端代码

test_task:
  agent: test_engineer
  context:
    - code_task             # 测试基于后端代码
```

### 你要搞懂
1. 多 Agent 各自产出不同文件：设计文档、Python 模块、Gradio UI、单元测试
2. `context` 链不是线性的——frontend 和 test 可以并行依赖 code
3. `allow_code_execution=True` + `max_execution_time=500` 用于需要运行代码验证的 Agent

## 常见问题

**Q: CrewAI 和 OpenAI Agents SDK 有什么区别？**
A: OpenAI SDK 是单 Agent 加 Tool/Handoff，适合对话路径不确定的场景。CrewAI 是固定多步骤管线（A→B→C），适合角色分工明确的工作流。

**Q: 能用 DeepSeek 跑吗？**
A: 可以。在 YAML 中把 `llm` 改成 `deepseek/deepseek-chat`，或在 `crew.py` 中传自定义 LLM 对象。`financial_researcher` 的 SerperDevTool 需要额外的 SERPER_API_KEY。

**Q: Task context 和直接把上一个 Task 的输出文本粘贴进去有什么区别？**
A: `context` 保留完整结构化数据，Agent 可以引用和引用前面的发现。手动粘贴会丢失上下文质量。

**Q: 层级流程和顺序流程怎么选？**
A: 如果你明确知道任务顺序 → Sequential。如果任务分配需要动态决策 → Hierarchical + Manager。

**Q: 代码执行需要什么前置条件？**
A: Docker 必须已安装并运行。`code_execution_mode="safe"` 会在独立容器中执行，不会影响宿主机。

**Q: 记忆系统会占用多少存储？**
A: SQLite LTM 很小（几 MB），LanceDB 向量库取决于嵌入维度和数据量。可以定期清理 `./memory/` 目录。
