## 先理解：5 步模式（贯穿所有 Lab）

每一个 LangGraph 应用都遵循这个骨架：

```python
# Step 1: 定义 State——在节点间流动的数据
class State(TypedDict):
    messages: Annotated[list, add_messages]

# Step 2: 创建图构建器
graph_builder = StateGraph(State)

# Step 3: 添加节点——每个节点就是一个函数
def my_node(state: State) -> State:
    ...
graph_builder.add_node("my_node", my_node)

# Step 4: 添加边——控制流
graph_builder.add_edge(START, "my_node")    # 固定路由
graph_builder.add_conditional_edges(...)     # 条件路由

# Step 5: 编译
graph = graph_builder.compile()
```

**`Annotated[list, add_messages]` 是什么？**  
`Annotated` 的第二个参数是 **reducer**——决定新值怎么和旧值合并。`add_messages` 是 LangGraph 内置的 reducer，会把新消息追加到消息列表末尾，而不是覆盖。

## Lab 1：图的基础——有没有 LLM 都一样（1_lab1.ipynb）

**目标：** 理解 LangGraph 本质上是 Python 函数编排器，LLM 只是可选组件。

### 无 LLM 版——随机句子生成器

```python
class State(BaseModel):
    messages: Annotated[list, add_messages]

graph_builder = StateGraph(State)

def random_sentence(state: State) -> State:
    nouns = ["Cats", "Dogs", "Robots"]
    adjectives = ["fuzzy", "loyal", "intelligent"]
    reply = f"{random.choice(nouns)} are {random.choice(adjectives)}"
    return State(messages=[{"role": "assistant", "content": reply}])

graph_builder.add_node("generator", random_sentence)
graph_builder.add_edge(START, "generator")
graph_builder.add_edge("generator", END)

graph = graph_builder.compile()
```

### 有 LLM 版——聊天机器人

```python
llm = ChatOpenAI(model="gpt-4o-mini")

def chatbot(state: State) -> State:
    response = llm.invoke(state.messages)   # 传入完整消息历史
    return State(messages=[response])

graph_builder.add_node("chatbot", chatbot)
graph_builder.add_edge(START, "chatbot")
graph_builder.add_edge("chatbot", END)
graph = graph_builder.compile()

# 调用
result = graph.invoke(State(messages=[{"role": "user", "content": "Hello"}]))
```

**执行流程：** `START → chatbot → END`（一条直线）

### 你要搞懂
1. State 的 `add_messages` reducer——为什么消息不会互相覆盖
2. `graph.invoke(state)` 返回的是什么（完整的最终 State）
3. LangGraph 不关心节点里是 LLM 还是纯 Python——它是一个通用编排器

## Lab 2：工具调用 + 条件路由 + 检查点（2_lab2.ipynb）

**目标：** 把直线变成循环——Agent Loop + 持久化记忆。

### Agent Loop 模式（最核心的图结构）

```python
llm = ChatOpenAI(model="gpt-4o-mini")
tools = [search_tool, notification_tool]
llm_with_tools = llm.bind_tools(tools)    # 绑定工具

graph_builder = StateGraph(State)

def chatbot(state: State) -> State:
    response = llm_with_tools.invoke(state.messages)
    return State(messages=[response])

graph_builder.add_node("chatbot", chatbot)
graph_builder.add_node("tools", ToolNode(tools=tools))

graph_builder.add_edge(START, "chatbot")

# 条件路由：chatbot 说的下一句话有 tool_call 吗？
graph_builder.add_conditional_edges(
    "chatbot",
    tools_condition,    # 预构建路由：有 tool_calls → "tools"，没有 → END
)
graph_builder.add_edge("tools", "chatbot")  # 工具执行完回到 chatbot

graph = graph_builder.compile()
```

**执行流程：**
```
START → chatbot → [有 tool_call?] → YES → tools → chatbot → [有 tool_call?] → NO → END
                     │                              ↑
                     └── NO → END                   └── 循环！
```

这就是 Agent Loop：**思考→行动→观察→思考→...**

### 检查点（Checkpointing）——让图记住对话

**为什么需要？** 一次 `invoke()` 是一个 "super-step"——Agent 在里面循环直到结束。但下一次 `invoke()` 时，图会忘记之前的事。检查点让状态跨调用持久化。

```python
# 内存检查点（单次会话内有效）
memory = MemorySaver()
graph = graph_builder.compile(checkpointer=memory)

config = {"configurable": {"thread_id": "1"}}  # thread_id 隔离不同对话
graph.invoke({"messages": [user_msg]}, config)

# SQLite 检查点（持久化到磁盘，重启后仍在）
import sqlite3
from langgraph.checkpoint.sqlite import SqliteSaver

conn = sqlite3.connect("memory.db", check_same_thread=False)
sql_memory = SqliteSaver(conn)
graph = graph_builder.compile(checkpointer=sql_memory)

# 查看历史
graph.get_state(config)
for snapshot in graph.get_state_history(config):
    print(snapshot)
```

### 你要搞懂
1. `bind_tools()` 怎么让 LLM 输出 tool_call
2. `tools_condition` 是 LangGraph 的预构建路由——判断最后一条消息是否包含 `tool_calls`
3. `ToolNode` 是预构建节点——自动执行 tool_call 并返回结果
4. Agent Loop = `chatbot → (条件) → tools → chatbot` 循环
5. `MemorySaver` vs `SqliteSaver`——一个在内存，一个在磁盘
6. `thread_id` 的作用——同一张图，不同对话隔离

## Lab 4 + sidekick.py：Sidekick 多 Agent 项目（核心）

**目标：** 构建一个 Worker + Evaluator 双 Agent 系统，带反馈循环和结构化输出。

### 架构

```
                    ┌──────────┐
                    │  START   │
                    └────┬─────┘
                         ▼
                  ┌─────────────┐
                  │   worker    │ ←── 执行任务（有浏览器工具）
                  └──────┬──────┘
                         ▼
                  ┌─────────────┐
           YES ←─ │worker_router│ ──→ NO
           │      └─────────────┘     │
           ▼                           ▼
    ┌─────────────┐            ┌─────────────┐
    │    tools    │            │  evaluator  │ ←── 检查工作质量
    └──────┬──────┘            └──────┬──────┘
           │                          ▼
           │                   ┌──────────────┐
           └──────────────────►│ eval_router  │
                               └──┬───────┬───┘
                    success/met │       │ retry
                    user_input  │       │
                        ┌───────┘       └──────┐
                        ▼                      ▼
                   ┌────────┐           ┌──────────┐
                   │  END   │           │  worker  │ ←── 带着反馈重新做
                   └────────┘           └──────────┘
```

### Rich State

```python
class State(TypedDict):
    messages: Annotated[list, add_messages]
    success_criteria: str              # 成功标准（用户提供）
    feedback_on_work: Optional[str]    # Evaluator 的反馈
    success_criteria_met: bool         # 任务完成？
    user_input_needed: bool            # 需要用户介入？
```

### Evaluator 结构化输出

```python
from pydantic import BaseModel, Field

class EvaluatorOutput(BaseModel):
    feedback: str = Field(description="Feedback on the assistant's response")
    success_criteria_met: bool = Field(description="Did the work meet the criteria?")
    user_input_needed: bool = Field(description="Is user input required?")

evaluator_llm = ChatOpenAI(model="gpt-4o-mini")
evaluator_with_output = evaluator_llm.with_structured_output(EvaluatorOutput)

def evaluator(state: State) -> State:
    result: EvaluatorOutput = evaluator_with_output.invoke(prompt)
    return State(
        feedback_on_work=result.feedback,
        success_criteria_met=result.success_criteria_met,
        user_input_needed=result.user_input_needed
    )
```

### 自定义路由函数

```python
# Router 1: worker 输出后——走 tools 还是走 evaluator？
def worker_router(state: State):
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return "evaluator"

# Router 2: evaluator 判断后——重试还是结束？
def route_based_on_evaluation(state: State):
    if state["success_criteria_met"] or state["user_input_needed"]:
        return END
    return "worker"   # 重试，worker 会在 SystemMessage 中看到 feedback
```

### 图的完整定义

```python
graph_builder = StateGraph(State)

graph_builder.add_node("worker", worker_node)
graph_builder.add_node("tools", ToolNode(tools))
graph_builder.add_node("evaluator", evaluator_node)

graph_builder.add_edge(START, "worker")
graph_builder.add_conditional_edges("worker", worker_router, {
    "tools": "tools",
    "evaluator": "evaluator"
})
graph_builder.add_edge("tools", "worker")
graph_builder.add_conditional_edges("evaluator", route_based_on_evaluation, {
    END: END,
    "worker": "worker"
})

graph = graph_builder.compile(checkpointer=MemorySaver())
```

### Worker 的动态 SystemMessage

Worker 的 prompt 根据 Evaluator 反馈动态变化：

```python
def worker_node(state: State) -> State:
    system_content = f"You are a helpful assistant. Success criteria: {state['success_criteria']}"
    if state.get("feedback_on_work"):
        system_content += f"\n\nFeedback on your previous attempt: {state['feedback_on_work']}"
        system_content += "\nPlease improve based on this feedback."

    messages = [SystemMessage(content=system_content)] + state["messages"]
    response = worker_llm_with_tools.invoke(messages)
    return State(messages=[response])
```

## 常见问题

**Q: LangGraph 和 LangChain 是什么关系？**
A: LangChain 是"链"（A→B→C 直线），LangGraph 是"图"（可以有分支、循环、并行）。LangGraph 是 LangChain 生态的一部分，但可以脱离 LangChain 单独使用。

**Q: 为什么 State 要用 `Annotated[list, add_messages]`？**
A: `Annotated` 的第二参数是 reducer，告诉 LangGraph 怎么合并新旧值。`add_messages` 是追加而不是覆盖。如果你用 `list` 不加 `Annotated`，每次节点返回都会覆盖整个列表。

**Q: `tools_condition` 和自定义 router 什么时候用？**
A: `tools_condition` 是标准路由——检查最后一条消息有没有 `tool_calls`。如果图里只有一个 LLM 节点和一个 tools 节点，用它就行。如果需要更复杂的决策（比如 Evaluator 判断重试还是结束），写自定义 router。

**Q: MemorySaver 和 SqliteSaver 怎么选？**
A: `MemorySaver` 在内存中，适合开发和 demo。`SqliteSaver` 持久化到磁盘，适合生产环境——重启后对话历史还在。

**Q: thread_id 必须唯一吗？**
A: 每个独立的对话应该有自己的 `thread_id`。同一 `thread_id` 的所有 `invoke()` 共享同一个状态历史。

**Q: 能同时用多个模型吗？**
A: 能。Lab 4 的 Worker 和 Evaluator 可以用不同的 `ChatOpenAI` 实例，甚至不同供应商（Worker 用 DeepSeek，Evaluator 用 Claude）。

**Q: 浏览器工具需要什么前置条件？**
A: Playwright 需要安装浏览器：`playwright install chromium`。Jupyter 环境下需要 `nest_asyncio.apply()`。Windows 可能还需要额外的 asyncio 配置。
