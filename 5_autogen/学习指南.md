## 核心认知模型

AutoGen 的三层架构对应三种用户：

```
AgentChat   ← "我只要 Agent 能聊天、调工具、组团队"
    │
Core        ← "我要精确控制谁给谁发什么消息"
    │
Distributed ← "我的 Agent 要跑在不同机器上"
```

**关键转变：** 在 OpenAI SDK / CrewAI / LangGraph 中，Agent A 直接调用 Agent B。在 AutoGen 中，Agent A 向 Runtime 发消息，Runtime 路由给 Agent B——调用者不知道也不关心接收者在哪里。

## Lab 1：AgentChat 入门（1_lab1_autogen_agentchat.ipynb）

**目标：** 用三个核心概念（Model / Message / Agent）跑通第一个 AutoGen Agent。

### 三要素

```python
from autogen_ext.models.openai import OpenAIChatCompletionClient
from autogen_agentchat.messages import TextMessage
from autogen_agentchat.agents import AssistantAgent
from autogen_core import CancellationToken

# 1. Model Client —— 封装 LLM
model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")

# 2. Message —— 通信载体
message = TextMessage(content="I'd like to go to London", source="user")

# 3. Agent —— 有名字、有系统指令、有模型
agent = AssistantAgent(
    name="airline_agent",
    model_client=model_client,
    system_message="You are a helpful assistant for an airline..."
)

# 发送消息，获取响应
response = await agent.on_messages(
    [message],
    cancellation_token=CancellationToken()
)
print(response.chat_message.content)
```

### 工具调用——最简单的形式

AutoGen 的工具就是一个 Python 函数，直接传给 Agent：

```python
def get_city_price(city: str) -> str:
    """Return the price of a ticket to the given city"""
    cursor.execute("SELECT price FROM tickets WHERE city = ?", (city,))
    result = cursor.fetchone()
    return f"Price to {city}: ${result[0]}"

agent_with_tools = AssistantAgent(
    name="smart_airline_agent",
    model_client=model_client,
    tools=[get_city_price],          # 零包装，直接传入
    reflect_on_tool_use=True         # 让 Agent 反思工具结果
)
```

### 执行流程

```
用户消息 → AssistantAgent.on_messages() → [需要工具?] → 调用 Python 函数
                                                    │
                                                    ▼
                                          返回 TextMessage 响应
```

### 你要搞懂
1. `OpenAIChatCompletionClient` 是模型抽象——可以用 OpenAI、DeepSeek、Ollama
2. `TextMessage` 的 `source` 字段——区分 user / assistant / system
3. `on_messages()` 是 AutoGen Agent 的统一入口（相当于 `Runner.run()`）
4. `reflect_on_tool_use=True` 让 Agent 在工具结果基础上再思考

class ImageDescription(BaseModel):

### 团队协作——RoundRobinGroupChat

这是 AutoGen AgentChat 最强大的模式：

```python
from autogen_agentchat.teams import RoundRobinGroupChat
from autogen_agentchat.conditions import TextMentionTermination

primary = AssistantAgent("primary", tools=[search_tool], ...)
evaluator = AssistantAgent("evaluator",
    system_message="Review the work. Reply 'APPROVE' if acceptable, or give feedback."
)

termination = TextMentionTermination("APPROVE")

team = RoundRobinGroupChat(
    [primary, evaluator],
    termination_condition=termination,
    max_turns=20
)

# 运行团队
result = await team.run(task="Research topic X")
```

**执行流程：**
```
task → primary → evaluator → [APPROVE?] → NO → primary（改进）→ evaluator → YES → 结束
         ▲                                                          │
         └──────────────────────────────────────────────────────────┘
```

这本质上是 Worker-Evaluator 反馈循环，和 LangGraph Lab 4 的 Sidekick 是同一个模式。

## Lab 3：AutoGen Core——进入中层（3_lab3_autogen_core.ipynb）

**目标：** 从高层 AgentChat 下沉到 Core API——自定义消息路由。

### 为什么需要 Core？

AgentChat 的 `RoundRobinGroupChat` 对你是黑盒——你不知道消息怎么流转的。Core 让你完全掌控：
- 谁给谁发消息
- 收到消息后做什么
- 什么条件下路由到哪里

### Core 三元素

```python
from autogen_core import AgentId, MessageContext, RoutedAgent, message_handler
from autogen_core import SingleThreadedAgentRuntime
from dataclasses import dataclass

# 1. 定义消息类型
@dataclass
class Message:
    content: str

# 2. 创建 RoutedAgent
class SimpleAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("Simple")

    @message_handler
    async def on_my_message(self, message: Message, ctx: MessageContext) -> Message:
        return Message(content=f"Received '{message.content}', I disagree.")

# 3. 创建 Runtime 并注册 Agent
runtime = SingleThreadedAgentRuntime()
await SimpleAgent.register(runtime, "simple_agent", lambda: SimpleAgent())
runtime.start()

# 发送消息
agent_id = AgentId("simple_agent", "default")
response = await runtime.send_message(Message("Hello"), agent_id)
print(response.content)
```

### 关键桥接模式——Core 包装 AgentChat

这是贯穿整个代码库的核心模式：

```python
class MyLLMAgent(RoutedAgent):
    def __init__(self) -> None:
        super().__init__("LLMAgent")
        model_client = OpenAIChatCompletionClient(model="gpt-4o-mini")
        self._delegate = AssistantAgent(     # AgentChat Agent 作为委托
            "LLMAgent",
            model_client=model_client,
            system_message="..."
        )

    @message_handler
    async def handle_message(self, message: Message, ctx: MessageContext) -> Message:
        # 把 Core Message 转成 AgentChat TextMessage
        text_message = TextMessage(content=message.content, source="user")
        # 调用委托 Agent
        response = await self._delegate.on_messages(
            [text_message],
            ctx.cancellation_token
        )
        # 把 AgentChat 响应转回 Core Message
        return Message(content=response.chat_message.content)
```

这个模式的意义：在 Core 的精确消息路由框架内，使用 AgentChat 的丰富能力（工具、结构化输出、流式等）。

### Agent 间通信

```python
class Orchestrator(RoutedAgent):
    @message_handler
    async def handle(self, message: Message, ctx: MessageContext) -> Message:
        # 向多个 Agent 并行发消息
        agent1 = AgentId("player1", "default")
        agent2 = AgentId("player2", "default")

        response1 = await self.send_message(message, agent1)
        response2 = await self.send_message(message, agent2)

        # 汇总结果
        return Message(content=f"Player1: {response1.content}\nPlayer2: {response2.content}")
```

**执行流程：**
```
Orchestrator
    │
    ├── send_message() ──► player1（LLM 决策）
    │
    └── send_message() ──► player2（另一个 LLM 决策）
    │
    ▼
汇总两个响应 → 判断胜负
```

### 你要搞懂
1. `RoutedAgent` + `@message_handler` 是 Core 编程的基本单元
2. `AgentId(type, key)` 是 Agent 的唯一地址——type 是注册名，key 是实例标识
3. `runtime.send_message()` 和 `self.send_message()` 的区别——前者从外部发，后者从 Agent 内部发
4. 桥接模式（`self._delegate`）让 Core 和 AgentChat 可以混合使用
5. `MessageContext` 提供了 `cancellation_token` 等运行时上下文

## Lab 4：分布式 gRPC（4_lab4_autogen_distributed.ipynb）

**目标：** 把 Agent 分布到不同进程/机器上运行。

### gRPC 架构

```
┌─────────────────────────────┐
│  GrpcWorkerAgentRuntimeHost │  ← 消息中枢（中央路由器）
│  localhost:50051            │
└──────┬──────────┬───────────┘
       │          │
       ▼          ▼
┌──────────┐ ┌──────────┐
│ Worker 1 │ │ Worker 2 │  ← 每个 Worker 是一个独立进程
│ Agent A  │ │ Agent B  │
└──────────┘ └──────────┘
```

### 启动分布式系统

```python
from autogen_ext.runtimes.grpc import GrpcWorkerAgentRuntimeHost, GrpcWorkerAgentRuntime

# 启动 gRPC 主机
host = GrpcWorkerAgentRuntimeHost(address="localhost:50051")
host.start()

# 创建 Worker 1
worker1 = GrpcWorkerAgentRuntime(host_address="localhost:50051")
await worker1.start()
await AdvocateAgent.register(worker1, "advocate", lambda: AdvocateAgent("advocate"))

# 创建 Worker 2
worker2 = GrpcWorkerAgentRuntime(host_address="localhost:50051")
await worker2.start()
await SkepticAgent.register(worker2, "skeptic", lambda: SkepticAgent("skeptic"))

# 现在两个 Agent 可以相互发消息，即使在不同进程中
```

### 单进程 vs 分布式对比

Lab 4 通过 `ALL_IN_ONE_WORKER` 开关让你对比：
- **True：** 所有 Agent 注册到同一个 Worker（单进程）
- **False：** 每个 Agent 注册到独立的 Worker（真正的分布式）

代码逻辑完全一样——这是 AutoGen 的核心价值：**换 Runtime 不需要改 Agent 代码**。

### 你要搞懂
1. `GrpcWorkerAgentRuntimeHost` 是中央路由器——所有消息经过它
2. `GrpcWorkerAgentRuntime` 是 Worker 进程的 Runtime——连接到 Host
3. 同一个 Agent 代码，用 `SingleThreadedAgentRuntime` 就是单进程，用 `GrpcWorkerAgentRuntime` 就是分布式
4. `AgentId` 在分布式场景下是全局唯一的

## 进阶：Self-Replicating Agent 生态系统（agent.py + creator.py + world.py）

这是本模块的巅峰——一个能自我繁殖的 Agent 系统。

### 架构

```
world.py
    │
    ▼
GrpcWorkerAgentRuntimeHost (gRPC Hub)
    │
    ▼
Creator Agent (creator.py)
    │
    ├── 读取 agent.py 模板
    ├── LLM 修改模板 → 新 Agent 代码文件
    ├── 导入新模块
    ├── 注册到 Runtime
    └── 发送 "Give me an idea" → 新 Agent 生成商业创意
    │
    ▼ (× 20)
20 个独特 Agent → 各自输出 idea_{n}.md
```

### creator.py — Creator 的核心逻辑

```python
class Creator(RoutedAgent):
    async def create_agent(self, i: int):
        # 1. 读取 agent.py 模板
        with open("agent.py", "r") as file:
            agent_code = file.read()

        # 2. LLM 修改系统消息，生成独一无二的 Agent
        response = await self._delegate.on_messages([...], ...)
        new_code = response.chat_message.content

        # 3. 写入新文件
        with open(f"agent_{i}.py", "w") as file:
            file.write(new_code)

        # 4. 动态导入并注册
        spec = importlib.util.spec_from_file_location(...)
        module = importlib.util.module_from_spec(spec)
        spec.loader.exec_module(module)
        await module.Agent.register(runtime, f"agent_{i}", ...)

        # 5. 向新 Agent 发消息
        await runtime.send_message(Message("Give me an idea"), agent_id)
```

### messages.py — 全局消息基础设施

```python
@dataclass
class Message:
    content: str

def find_recipient() -> AgentId:
    """扫描所有 agent*.py 文件，随机选一个同伴"""
    agent_files = glob.glob("agent*.py")
    agent_names = [os.path.splitext(f)[0] for f in agent_files]
    agent_names.remove("agent")  # 排除模板本身
    return AgentId(random.choice(agent_names), "default")
```

1. Creator 模式：一个 Agent 动态生成和注册新 Agent
2. `importlib` 动态导入——运行时加载新代码

## 常见问题

**Q: AgentChat 和 Core 怎么选？**
A: 快速原型用 AgentChat（`AssistantAgent` + `RoundRobinGroupChat`）。需要精确控制消息路由、动态创建 Agent 时用 Core（`RoutedAgent` + `SingleThreadedAgentRuntime`）。

**Q: 桥接模式为什么这么重要？**
A: Core 的 `RoutedAgent` 给你精确的消息路由控制，但它不自带 LLM 能力。桥接模式让你在 Core 框架内复用 AgentChat 的 LLM 调用、工具、结构化输出等能力。这是本代码库最常用的模式。

**Q: 分布式真的有用吗？**
A: 对于大多数场景，单进程就够了。但如果你有计算密集型 Agent（如本地推理、视频处理），或者需要容错隔离（一个 Agent 崩溃不影响其他），分布式就很有价值。

**Q: AutoGen 和 LangGraph 哪个好？**
A: LangGraph 的思维模型是"图"（节点+边），AutoGen 的思维模型是"消息"（发送+接收）。如果流程是固定的 DAG，用 LangGraph。如果 Agent 需要动态发现、自发通信、分布式部署，用 AutoGen。

**Q: AutoGen 进入维护模式了，还值得学吗？**
A: 值得。消息驱动、分布式 Agent 的架构模式在 Microsoft Agent Framework 中延续——学的不是 API，是架构思维。
